# 1. Requirements

What has to be built, agreed before anything else starts.

1. **Elaborate the requirements until no misinterpretation is possible and every unclear
   point is cleared.** Explicit beats implicit: write each requirement down, including
   what is out of scope.
2. **Ask questions until finished.** Interview, challenge and brainstorm first, one topic
   at a time; narrow the scope only once the picture is clear. The owner approves the
   result.
3. **No architecture or design before the requirements are complete and approved.**
4. **Every requirement can be tested:** it states the required behaviour in a way a test
   can check.
5. **Requirements about real-world input come from real samples.** Rules that interpret
   texts, data or user behaviour are derived from, and checked against, a representative
   set of real examples, never from imagination.
6. **A choice with more than one reasonable reading is asked, not guessed:** above all
   one that changes the owner's own files, data or configuration.
7. **The owner's preferences are recorded as they come up,** and each becomes a
   requirement or a planned item.
